The design is careful. Unit tests cover the scary bits: sherpa exit(-1) by family, language into the styler, sanitizer loops, whisper.cpp decode status. I would merge after a device smoke, not before.

What the code actually does

  • iOS WhisperKit now sets detectLanguage when language is Automatic. That bug is real: WhisperKit derives detection from usePrefillPrompt, so Automatic was silently English.
  • Detected language reaches the styler on both platforms, so Automatic + Hindi can get a danda instead of a Latin full stop.
  • iOS gets TranscriptSanitizer, including the repetition-loop collapse Android just grew.
  • whisper.cpp decode status is no longer discarded (empty transcript used to look like silence).
  • Audio levelling is applied to the in-memory copy only. WAV on disk and gateway bytes are untouched. Confirmed in both LocalModelManagers.
  • Fast / Balanced / Accurate, plus a Whisper-only custom-word list. Sherpa decoding method comes from model family, not from the setting alone.
  • Engine preload when model or accuracy changes, with a loading label.

Why it is not a merge today

The IME/sherpa live path never sees the new gain. SpeechAudioConditioning is called from whole-file transcribe. startIncrementalSession / startSherpaIncrementalSession feed raw chunks into sherpa. For Parakeet that is the keyboard path. Whisper still gets levelling because it still decodes at finish. Documented in comments, missing from the PR body.

Author’s hardware list, still outstanding:

  • Hindi dictation, Automatic, Whisper: expect ।
  • SenseVoice Chinese: expect 。
  • Change accuracy, dictate immediately (preload)
  • Any CTC model on Balanced (the old exit(-1) path)

CI does not exercise native decode, JNI, or a microphone.

Nits

Android Balanced copy says "Beam search where it is cheap". whisper.cpp Balanced is still greedy (whisperBeamSize = 0). Beam is Accurate only. Sherpa transducers do get beam on Balanced. iOS WhisperKit has no beam at all; Accurate only raises temperatureFallbackCount.
